# Pre-registration: ED K=4, N_ENGINES=8 (C0003 replication) first silicon pass (written 2026-09-17, 22:50, before the build finished)

Purpose (docs/corrections.md C0003): lift the metered fabric delta above
baseline drift by running eight identical engines on the same input
stream; per-engine energy is then delta-P / 8 with N stated. This pass
is the correctness and timing gate for that bitstream, not an energy
measurement (no meter yet).

Build under test: ENGINE=1, ED_K=4, N_ENGINES=8, BAKED_WEIGHTS=1, built
by host/vivado/build_engine.tcl (global synthesis) with the C0044
ed_conv_layer.v in the project — the first ED K=4 bitstream WITH the
fix. Server build 4. Pre-write checks as always, plus N_ENGINES=8 read
from the .hwh.

## Predictions

1. Timing: WNS may fall well below the N=1 build's +0.508 (eight-way
   fan-out of the input stream, eight engines' worth of placement).
   A negative WNS is a legitimate C0003 outcome ("does not close at
   N=8 at 100 MHz; try N=4 or a lower clock"), recorded, not worked
   around. If WNS >= 0 the pass proceeds.
2. Correctness: 16/16 bit-identical — only instance 0 drives the DMA;
   the replicas' outputs are consumed unconditionally.
3. Latency: **the same per-sample engine-only numbers as the K=4 N=1
   record** (experiments/board_ed_k4_20260905.md build-4 table: mean
   688.5 us, 554.8-815.8) to within the timer's resolution — the
   replicas share the stream and advance in lockstep; instance 0's
   tready speaks for all. Any change is a bug in the replication
   wiring (or a replica falling out of lockstep), not a design effect.
4. Resources: roughly 8 x the K=4 engine — ~9-10k LUTs and ~85-95 BRAM
   tiles of 140 (K=8's engine was 1,161 LUT / 11.5 tiles; K=4's is
   near that with fewer, deeper banks); DSP 0. The exact numbers are
   the deliverable of this build for the meter session.
5. Server overhead ~117.5 us, unchanged.

## What would falsify

- CRC mismatch: replication wiring (or DONT_TOUCH pruning) broke
  instance 0's stream.
- Latency differing from the N=1 record by more than the timer's
  resolution: the replicas are stalling instance 0.
- BRAM above ~100 tiles: the per-engine BRAM estimate is wrong; N=8
  for dense P=4 (planned next) would then need re-checking.

## Outcome

(2026-09-17, 23:09; experiments/board_ed_k4_x8_20260917.md)

1. Timing: **closed**, WNS +0.430 / WHS +0.034 — proceeded.
2. Correctness: **16/16 bit-identical**, 4,800 further inferences with zero mismatches — held.
3. Latency: **identical to the N=1 record on every sample** (mean 688.5, 554.8-815.8) — held.
4. Resources: 11,733 LUT, 7,539 FF, **86 BRAM tiles** (in the 85-95 range), DSP 0 — held.
5. Server overhead 117.5 us — held.
Nothing falsified.
