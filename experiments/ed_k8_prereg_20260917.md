# Pre-registration: ED K=8 first silicon pass (written 2026-09-17, before the measurement)

Written BEFORE the board is powered on the K=8 image, so the comparison
cannot be tuned after the fact (CLAUDE.md M7). Same discipline as
dense_p4_prereg_20260906.md, every prediction of which held.

Build under test: ENGINE=1, ED_K=8, BAKED_WEIGHTS=1, N_ENGINES=1, built
by host/vivado/build_engine.tcl (builds/ed_k8_20260917_2106, bitstream
2026-09-17 20:57:21, WNS +0.332 / WHS +0.025 from the run whose
out-of-date flag Vivado reported clear). Server build 4 (unchanged
ELF). Pre-write checks: .hwh ENGINE=1 ED_K=8 DENSE_P=4 BAKED=1
N_ENGINES=1, MT41J128M16, HP0=1, three MEMRANGEs, BOOT.bin PL partition
byte-equal to the .xsa bitstream, bitstream differs from every earlier
build. Card md5 788d422b... verified after write.

Source of the predictions: experiments/latency_sim/ksweep_c0035/ed_k8.txt,
the same 16 check samples the board runs, engine_busy cycles at 100 MHz.
K=4 on silicon came in +1.5 % above its simulation (688.5 vs 678 us),
so the "expected" column applies that same factor.

## Predictions

1. Correctness: 16/16 bit-identical (the K=8 configuration was
   bit-identical in the baked AXIS harness with the hostile handshake
   on 2026-09-06; K is a parameter of the same silicon-proven RTL).
2. Engine-only latency, mean over the 16 samples: **564.6 us** from
   the cycle model, **~573 us** expected with the K=4 silicon
   factor. Range 483.2 to 642.2 us (sample 5, digit 1, fastest;
   sample 14, digit 8, slowest -- same ordering as K=4).
3. Spread: about 1.33x (max/min), narrower than K=4's 1.47x, because the
   data-dependent scatter term shrinks with K while the 45.2k-cycle
   sweep floor does not.
4. Against ED K=4 on silicon (688.5 us): **1.2x faster** (sim 67,756 ->
   56,464 cycles = 1.20x). Against dense P=4 (1048.9 us): 1.84x.
5. Server overhead ~117.5 us per pass, unchanged (same ELF).
6. Resources: BRAM tiles roughly double K=4's 12.5 (per-bank membrane and
   weight banks, eight of each); DSP 0; LUT/FF above K=4's.

## What would falsify

- Any CRC mismatch: a K=8-specific silicon bug simulation did not see.
- Mean more than ~3 % off the expected value: the K-split of the cycle
  model (45.2k floor + 90.3k/K scatter) is wrong at K=8.
- Mean at or below the dense P=8 prediction (532 us) would mean the
  floor term is wrong and the K = P ~ 6.6 crossover analysis is
  retracted (this needs dense P=8 on silicon to settle, Build 4).
- Spread wider than K=4's: something other than scatter is data-dependent.
