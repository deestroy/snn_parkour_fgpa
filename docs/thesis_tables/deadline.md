# Deadline reading: per-sample latency distributions against perception periods

Generated by make_tables.py from the per-sample cycle/board files. 'Max sustainable rate' is the perception rate at which the WORST sample still meets its period (1 / worst latency). The board rows are what host/board/conv_server.c calls engine-only ticks: the ARM global timer bracketing one_pass, i.e. cache flush, both DMA transfers, the busy-poll and the cache invalidate. It excludes UART framing and CRC only, NOT the DMA -- see the +8.3 / +10.9 / +20.0 / +29.4 us decomposition in docs/decisions.md; miss rate at a given rate is the fraction of samples whose latency exceeds that period. The robot's control period is 100 ms (10 Hz), so the budget fraction column is worst latency / 100 ms. Both engines meet every period up to 200 Hz on every set; the difference between them appears only above that, and in the spread.
